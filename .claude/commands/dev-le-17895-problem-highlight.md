## 절대 규칙

1. **R-09 절대** — 원문 단어에 **강조 태그만 부착**. 단어 추가/변경/삭제/띄어쓰기 변형 금지. 태그 strip 시 원문과 byte 100% 일치.
2. **`## 문제` 섹션만 대상** — `## 답안`/`## 목차`/`## 원본`(채점기준) 섹션은 건드리지 않음 (각각 emphasis-sweep 소관 또는 강조 금지).
3. **문제 4태그 사용** — `[em1]`/`[em2]`/`[em3]`/`[u]`. 답안 강조용 em과 **색 통일**(문제도 em 재사용 — 사용자 지시 2026-05-25). em4/con/fact/case/bridge/key/red/blue/purple는 문제 미사용.
4. **신규 태그/뷰어 코드 수정 금지** — 위 4태그는 `merge.html` 화이트리스트(정규식 + CSS + stealth) 기존 등록분. 새 색 도입 X.
5. **Opus + ultrathink 강제** (의미 분석 — 어떤 단어가 쟁점/결론을 트리거하는지 판단). Sonnet/Haiku 금지.
6. **자동 substring 매칭 X** — 의미 기반 정확 분석. (예: "통지"가 항상 트리거는 아님 — 문맥상 누락·흠결일 때만.)
7. **과다 강조 금지** — §3 상한 초과 시 QA 반려. 법률 문제는 거의 모든 문장이 의미 있으나 다 칠하면 트리거 식별 기능 상실.
8. **QA 권고 근거 의무** — 부장판사·강사 QA가 지적 시 파일경로+라인/PDF+페이지/룰 명시 근거 제시 강제. 근거 없으면 메인이 reject.

## 강조 태그 4종 (답안 em과 색 통일)

답안 강조용 em1~3을 문제에도 재사용 — 색 통일(사용자 지시 2026-05-25). **신규 색 0**.

| 태그 | 색 (hex) | 의미 | merge.html 근거 |
|------|----------|------|------|
| `[em1]` | 빨강 배경 #c92a2a | **① 논점 트리거** — 쟁점을 발생시키는 사실·조건어 | CSS line 466 + 정규식 + stealth |
| `[em2]` | 노랑 배경 #f59f00 | **② 결론 근거** — 결론을 좌우하는 핵심 요건사실 | CSS line 467 + 정규식 + stealth |
| `[em3]` | 파랑 배경 #1971c2 | **③ 사실관계 키** — 인물·날짜·금액·목적물 식별자 | CSS line 468 + 정규식 + stealth |
| `[u]` | 밑줄 | **설문 요구** — 묻는 동작·선택지 제약 | 기존 밑줄, 색 강조와 중첩 OK |

- em1~3 모두 stealth(다운로드/TTS) strip 목록 포함 → **음성 청취 영향 0** (시각 학습 전용).
- 문제·답안 색 통일: 답안 em1~4(배경 빨/노/파/보)와 동일 색을 문제 ①②③에 재사용. 의미 라벨(논점트리거/결론근거/사실관계키)로 문맥 구분.

## 강조 대상 판단 기준 (§ = 시범 샘플 docs/tts-new/_problem_highlight_sample.md)

### ① 논점 트리거 `[em1]`
"이 단어 때문에 그 논점을 써야 한다"는 방아쇠. **출제자가 일부러 비틀어 넣은 조건어**.
- 예: `단독으로`(공유물 처분), `사망`(상속·대습), `통지 없이/동의 없이`(흠결), `기간 도과/제출하지 않`(실권효), `보조적 상행위`(상사시효), `미성년자`(필요적 변호), `쌍방 항소`(불이익변경금지).

### ② 결론 근거 `[em2]`
"이 사실이 있어서 결론이 이쪽으로 간다"는 결정적 사실. ①과 겹치면 **결론 직결 쪽(em2) 우선**.
- 예: `동의서를 제출하지 않았다`(취하 무효), `변제기 2022. 6. 30.`(시효 기산점), `최대한의 금액을 청구`(청구액 방향), `재통지 누락`(기각결정 위법).

### ① 논점 트리거 ↔ ② 결론 근거 경계 판정 플로차트 (QA 권고 2 — 둘 중 헷갈릴 때)

```
강조 후보 단어/구
  │
  ├─ Q1. 이 표현이 "어떤 논점을 써야 하는지"를 가리키나? (쟁점 발생 신호)
  │       └─ YES & 결론 방향은 아직 미정 → [em1] (논점 미정사실 / 논점트리거)
  │
  ├─ Q2. 이 사실이 "결론이 어느 쪽으로 확정되는지"를 좌우하나? (결론 직결)
  │       └─ YES → [em2] (결론 확정사실 / 결론근거)
  │
  └─ Q3. 둘 다 YES (논점도 유발 + 결론도 좌우)?
          └─ 결론 직결 우선 → [em2]
```

- **한 줄 기준**: **논점 미정사실 = `[em1]`(논점트리거), 결론 확정사실 = `[em2]`(결론근거)**.
- `em1`(논점트리거) = "이 단어 때문에 *쟁점이 생긴다*"(방향 미정). `em2`(결론근거) = "이 사실 때문에 *결론이 정해진다*"(방향 확정).
- 예: `사망`(상속 논점 유발, 누가 상속·시효 어떤지 미정 → em1) vs `사망 2024. 12. 21.`(상속 개시·승계 시점 확정 → em2). `보조적 상행위`(상사시효 논점 → em1) vs `변제기 2022. 6. 30.`(시효 미완성 결론 확정 → em2).

### 효과발생 기준일(사망일·변제기 등) 분류 가이드 (QA 권고 4)

**효과발생 기준일(변제기·사망일·기간 만료일 = 그 날 법적 효과 발생) → `[em2]`(결론근거). 단순 사안 식별일(계약일·대여일) → `[em3]`(사실관계키).** 판단법: "그 날 무슨 법적 효과가 생기나?"에 답 있으면 em2, "언제 있었던 일"이면 em3. (시범 샘플 §7 표 참조.)

### ③ 사실관계 키 `[em3]`
사안 식별 앵커. **반복 인물은 첫 등장 1회만**. 모든 날짜·금액 X — 쟁점·청구액 직결만. (단, 효과발생 기준일은 위 가이드대로 em2로 — em3 아님.)
- 예: 인물명(첫 등장), 핵심 금액, 단순 사안일(계약·대여일), 목적물(X토지 등).

### 설문 `[u]`
사실관계 뒤 묻는 문장의 요구 동작(`설명하시오`/`판단·이유`/`타당한지 여부`)·선택지 제약(`각하/기각/인용 중 선택`).

## §3 과다 강조 방지 (QA 반려 기준)

1. **유형별 상한 (설문 1개당)**: em1(논점트리거) ≤5, em2(결론근거) ≤4, em3(사실관계키) ≤6 권장. 민사서류·종합사례는 설문 수 비례 +50%까지.
2. **인물/날짜/금액 전수 금지**: 반복 인물 첫 등장 1회만 em3. 쟁점·청구액 직결 날짜·금액만.
3. **단답 설명형은 출제 주제어만**: 사실관계 없는 "X에 대하여 설명하시오" → `[em1]X[/em1]` 1~2개 + 설문 `[u]`. ②③ 억지 생성 금지.
4. **문장 통째 칠 금지**: 단어/짧은 구 단위. 긴 핵심 문장은 답안에서 `[u]` 처리. **인물 주어·배경 시간어는 강조 밖**, 트리거 핵심구만(예: `아버지는 [em2]동의서를 제출하지 않았다[/em2]`, `만료일까지 [em1]항소이유서를 제출하지 않았다[/em1]`).
5. **em4/con/fact/case/bridge/key 등 나머지 답안 태그 문제 사용 금지** (규칙 3 재강조 — 문제는 em1~3 + u만).
6. **em3(사실관계키) 상한 운영 — 당사자 다수일 때 (QA 권고 5)**: 연대보증인·공동피고·공동상속인 등 동일 지위 당사자가 다수여서 em3 상한(6)을 넘길 우려 시 →
   - (a) **쟁점·청구 직결 당사자 우선** em3. 단순 배경 인물(비상속인 며느리·손자, 청구 대상 아닌 자)은 강조 X.
   - (b) 동일 지위가 3인 이상이고 **개별 식별이 풀이에 불필요**하면 대표 1~2인만 em3 후 나머지 생략(상한 보호). 단, **각자 청구액·항변이 달라 개별 거명이 결론에 필요하면 전원 em3 허용**(상한 +50% 적용, 사례 복잡도에 비례).
   - (c) 연대보증인처럼 인원수 자체가 트리거인 경우(연대채무 분할/부진정연대) → 인물은 em3 최소화하고 `[em1]연대보증[/em1]` 같은 **관계어**로 논점 신호. 인물 나열보다 관계 강조가 식별 효율 높음.
7. **사례 유형별 트리거 패턴 (QA 권고 — 누락방지)**: 아래 유형은 핵심사실 누락이 잦으므로 우선 점검.
   - **공범 사례(합동범·공동정범)**: 시간·장소적 협동 인정 사실(망보기·역할분담 등)은 `[em1]` 논점트리거.
   - **금전청구 사례**: 일부변제·이자지급 등 소멸시효 중단(승인)·기산점 재산정 사실은 `[em2]` 결론근거.

## 수행 (파일별)

1. Read로 .md 전체 읽기 — `## 문제` 섹션 식별 (`## 목차` 직전까지, 목차 없으면 `## 답안` 직전까지).
2. `## 문제` 본문 의미 분석 (ultrathink):
   - 쟁점 유발 조건어 → `[em1]` (논점트리거)
   - 결론 좌우 요건사실 → `[em2]` (결론근거)
   - 사안 식별자(인물 첫등장/핵심 날짜·금액/목적물) → `[em3]` (사실관계키)
   - 설문 요구 동작·선택지 제약 → `[u]`
3. §3 상한 자체 점검 (초과 시 우선순위 낮은 em3부터 제거).
4. Edit으로 `## 문제` 섹션에만 인라인 태그 삽입.
5. **R-09 self-check**: 태그 strip(`sed -E 's/\[\/?(em1|em2|em3|u)\]//g'`) 후 원본 `## 문제`와 diff → 0 byte 차이 확인.
6. 논점-단어 매핑 근거 기록 (각 강조가 어느 논점/결론에 대응하는지).

## sweep (다수 파일 일괄)

emphasis-sweep과 동일 디렉토리 분담. Opus 5~10명 병렬, 디렉토리별 `## 문제` 섹션만.
- 각 Opus 프롬프트에 §본 스킬 규칙 + 시범 샘플 경로(`docs/tts-new/_problem_highlight_sample.md`) 첨부.
