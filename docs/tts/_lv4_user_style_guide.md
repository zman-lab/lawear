## 1. 빠른 참조 (변환 서브에이전트용)

### PDF 한 Case → Lv.4 변환 7단계

1. **PDF 결론(Ⅰ)을 한 줄로 압축** → "결론, ~" 형식
2. **사실관계/당사자 이름/구체 날짜 제거** (단 시효계산 필수 날짜는 유지 — R-02)
3. **근거(Ⅱ) 계층 구조(1.(1)(2)(3))를 평면 번호(1. 2. 3.)로 flatten**
4. **조문 인용은 앞배치 + 번호만** ("제 397조 금전채무불이행 특칙으로 ...")
5. **판례는 결론만** ("판례는 ~ 했다", 판례번호 완전 제거)
6. **학설 대립 완전 제거** (판례 입장만 기재)
7. **문제/목차/F(포섭) 별도 섹션 없음** — 필요하면 마지막 번호에 사안포섭 통합

### 길이 체감 규칙

- Case 전체 10~25줄 (PDF 원본의 1/3~1/4 압축률)
- 평균 번호 수 6~8개 (최소 0개, 최대 13개)
- 각 번호 1~3줄 (판례 본문 긴 경우 한 번호가 5~6줄도 가능)

## 2. 일관 패턴 (모든 Case 적용)

### P-01. 결론 한 줄 단독 ⭐

**패턴**: 첫 줄에 "결론, ~" 형식으로 사안에 대한 답을 한 문장(또는 복문)에 기술.

**사용자 긍정 예시**:
- Case 1: `결론, 원금과 지연손해금을 청구 할 권리가 있다.`
- Case 12: `결론, 취소 할 수 있다.` (최단)
- Case 27: `결론, 무권한자의 처분행위로 무효인 제2양도계약으로 제2양수인은 채권을 취득한바가 없으니, 이로써 손해를 입었다 볼 수 없고, 진정한 채권자인 제3양수인이 법률상 원인없이 이득을 얻었다 볼 수 없다,` (최장 복문)
- Case 29: `결론, 화재원인이 불명이라면, 임차건물 부분은 임차인의 책임이고, 그 외 부분은 임대인이 증명하지 못한바 임대인의 책임이다,` (두 쟁점 병렬)

**잘못된 변환 (부정)**:
- ❌ `결론. ~` (마침표 사용 — 쉼표여야 함)
- ❌ `결론: ~` (콜론 사용 — R-05 위반)
- ❌ `Ⅰ. 결론` 로마숫자 섹션
- ❌ 결론을 두 줄로 나누기

**PDF 원본 추출 방법**:
- PDF의 "Ⅰ. 결 론" 직후 해시태그로 표시된 정답 (보통 PDF 말미 "① ~"로 표시)
- Case 별 복수 결론(① ②)인 경우 → 결론 문장 내에 쉼표로 연결하거나 "A이고 B이다" 식으로 병렬

**변환 가이드**:
- PDF 해시태그("① 모두 청구할 권리가 있다")를 확인 후 사안에 맞춰 "결론, ~" 문장화
- 결론 문장 끝에 쉼표(,) 혹은 마침표(.) 사용 — 사용자 작성본은 혼용하지만 **쉼표가 다수** (Case 22, 23, 24, 27, 28, 29, 30은 쉼표)
- 복잡한 쟁점(Case 27, 30)은 결론 자체를 복문으로

### P-02. 번호 매김 답안 (1, 2, 3, ...) ⭐

**패턴**: 결론 직후 `1. ~` `2. ~` 평면 번호로 명제 나열.

**특징**:
- 소계층(1-1, 1-2) 없음 — 전부 평면
- "Ⅱ. 근거 → 1. ~ → (1) ~ → ① ~" 식 PDF 계층을 모두 1차원으로 펼침
- 번호 뒤 점(`.`) + 공백 + 명제 시작

**사용자 예시**:
```
1. 청구의 병합,
소비대차계약 기한 반환 청구와 지연손해금은 별개의 소송물로 객관적 병합에 해당한다.
원금청구가 지연손해금청구의 선결관계이므로 관련적 병합에 해당한다.
```
- 번호 뒤 쉼표 후 줄바꿈 → 본문 시작 (Case 1의 번호 1 패턴)

```
2. 금전반환청구 요건으로는 소비대차계약 체결 사실, 금전을 지급 한 사실, 변제기 도래를 요건으로 한다.
```
- 번호 + 짧은 본문 한 줄 완결 (Case 1의 번호 2 패턴)

**변환 가이드**:
- PDF "1. ~" 또는 "(1) ~" 또는 "①"을 만나면 모두 평면 번호 1 하나로 통합
- 번호가 서로 다른 계층에 있었더라도 같은 번호체계로 flatten
- 한 번호에 1~3줄 본문 (판례 긴 경우 5~6줄)

**번호 오류/부재 보존 원칙**:
- Case 9: 번호 0개 (1줄 명제만) — 사용자가 의도적으로 생략
- Case 28: 번호 3 빠짐 (1, 2, 4, 5) — 사용자 오류지만 **보존**
- 변환 서브는 번호 재정렬 금지 (사용자 패턴 존중)

### P-03. 조문 인용 — "제 XXX조" 띄어쓰기 일관 ⭐

**패턴**: 조문번호 앞에 반드시 공백 (`제 397조`, `제 214조`, `제 126조`).

**근거**:
- 사용자 작성본 30개 Case 전체에서 일관 → **의도적 습관** (오타 아님)
- R-19/R-21에서 "조문번호 아라비아 유지"는 지켜짐 — 한글 서수 변환 X
- 룰 R-19 기준(`제250조`, 띄어쓰기 없음)과 **상충하지만 사용자 패턴 우선**

**변환 가이드**:
- Lv.4 한정으로 "제 XXX조" 유지 (Lv.1/2/3는 R-19 따라 띄어쓰기 없음)
- 항/호도 동일: "제 482조 제 2항 제 5호", "제 135조 제 2항"
- **조문명은 Lv.4에서 번호만**. 제목 삽입 X (R-16 앞배치 대신 번호만).
  - 예외: 번호 바로 뒤에 조문 핵심 취지 이어서 기술 ("제 397조 금전채무불이행 특칙으로 ...")

### P-04. 판례 인용 — "판례는 ~ 했다" ⭐

**패턴**:
- "판례는 ~ 인정한다" / "판례는 ~ 했다" / "판례는 ~ 본다"
- 판례번호 완전 제거 (R-01)
- 판례 논리는 **결론만** 발췌하되, 복잡한 전합판결(Case 2, 5, 11, 27)은 판례 본문을 번호 내에 거의 그대로 이식

**사용자 예시**:
- Case 4 번호 2: `판례는 수급인이 원시취득 했을 경우 하수급인도 수급인에 대해 제 666조의 저당권설정청구권을 인정한다.` (결론 한 줄)
- Case 7 번호 7: 판례 본문 절반 이식 (동시이행항변권 유지 + 상계 대항 로직)
- Case 29 번호 7: 종전 판례 + 변경 판례 대비 구조 (번호 한 개 안에)

**판례 변경 처리**:
```
N. 종전 판례는 ~ 했으나,
    최근 변경 판례는 ~ 이다.
```
- Case 8-2, 29에 나타남
- **"종전" → "변경"의 이유**까지 별도 번호로 분리하는 경우도 있음 (Case 8-2: 번호 3~5)

**변환 가이드**:
- 판례 전문 인용이 필요한 경우 → 번호 하나를 길게
- 논점별로 판례 결론만 필요한 경우 → 짧게 한 줄

### P-05. 학설 대립 완전 제거 ⭐

**패턴**: 학설 대립이 있는 주제라도 **판례 입장만** 기재. "학설은 A, B, C로 나뉜다"는 표현 전무.

**근거**:
- Case 1~30 전체에서 "학설"이라는 단어 자체가 없음
- 판례와 학설이 대립하는 주제(Case 12 일부취소 법리, Case 20 무권대리인 책임 성질 등)도 판례만

**변환 가이드**:
- PDF에 학설 대립 섹션 있으면 → **전부 제거**
- 판례 결론 또는 통설에 준하는 실무 입장만 기재

### P-06. 한자 인명 → 한글 변환 ⭐

**패턴**: PDF의 甲/乙/丙/丁은 사용자 작성본에서 **모두 한글 (갑/을/병/정)** 또는 일반 당사자 표기 (A, B, C 유지).

**예시**:
- PDF "甲은행" → 사용자 "갑은행" (Case 8 대응 8-1/8-2 PDF는 "甲은행", 사용자는 갑 문자 쓰지 않고 "은행"으로 지칭)
- PDF "乙은 甲 소유의 X건물" → 사용자 Case 9 "甲과 丙의 매매계약" → "제1매수인", "제2양수인" 같은 역할 명칭으로 재지칭

**역할 명칭 우선 패턴**:
- Case 9~10: "제1매수인", "제2양수인", "매도인" — 이름 아닌 역할로
- Case 13: "채권자", "연대보증인", "채무자"
- Case 19: "본인", "무권대리인", "상대방"

**단, A/B/C/D/E는 유지**:
- Case 2: `E는 채무자의 특정승계인` — E를 한글화하지 않음
- Case 8-1: "양수인", "양도인" (B 대신 역할로)

**변환 가이드**:
- 한자(甲乙丙丁) → 한글 (갑을병정) OR 역할 명칭
- 알파벳 A/B/C/D/E는 그대로 유지
- 사안에서 2명만 등장하면 이름 반복 줄이기 (R-17)

### P-07. 숫자/날짜 처리

**패턴**:
- **금액**: 한글화 X (Lv.4에서는 예외적으로 "1000만원", "1억원" 유지) — 단 R-21 일반 금액 한글화와 상충
  - 실제 사용자 작성본: 구체 금액 대부분 **삭제** (Case 1에서도 1000만원 삭제됨), 법리만 남김
  - Case 30: "700만원", "300만원" 전부 **제거** — 결론에 없음
- **날짜**: 시효 계산 필수는 유지 (Case 6 "1990년 9월 20일"), 단순 사실관계는 삭제
- **조문번호**: 아라비아 숫자 그대로 (`제 397조`, `제 5항` — R-19 준수)
- **목록 번호**: 1. 2. 3. 그대로 (R-20 준수)

**변환 가이드**:
- 금액이 쟁점(예: 과실상계 비율)이면 유지, 단순 사실관계면 제거
- 일반화 가능한 숫자는 제거 (Lv.4는 법리 중심)

### P-08. 요건 나열 패턴

**패턴**: "A요건, B요건, C요건이다" — 쉼표로 연결, "을 요한다" 또는 "~이다" 말미.

**예시**:
- Case 1 번호 2: `금전반환청구 요건으로는 소비대차계약 체결 사실, 금전을 지급 한 사실, 변제기 도래를 요건으로 한다.`
- Case 19 번호 6: `제 135조 상대방에 대한 무권대리인의 책임 요건으로는, 대리행위가 있을것, 표현대리가 성립하지 않을것, ..., 상대방은 선의 무과실일것이다,`

**말미 표현**:
- "~을 요한다", "~이다", "~할것이다"
- PDF의 "요건이 갖추어져야 한다" → 사용자 "을 요한다" 또는 "이다"로 단축

### P-09. 사안 포섭 통합 ⭐

**패턴**: 별도의 "F(사안 포섭)" 섹션 없음. 사안 포섭이 필요하면 **마지막 번호 또는 결론에 통합**.

**사안포섭 위치**:
1. **결론 자체에 통합** (Case 27): 결론 = 판례 이유 이식
2. **마지막 번호**: 번호 7, 8, 10에 "사안에서 ~" 문장
3. **아예 생략** (Case 1, 2, 4): 법리 전개만으로 답안 구성

**예시**:
- Case 14 번호 7: `사안에서 매매계약 후 계약금의 교부가 있었고 특별한 약정이 없으며, 일방의 이행 착수전에 매도인은 계약금의 배액을 적법하게 공탁 한 뒤, 내용증명 우편으로 계약 해제의 의사표시를 하였으므로, ...`
- Case 30 번호 7: "구상권 범위는 제삼자의 부담부분에 국한 된다" — 결론 재확인

**변환 가이드**:
- 쟁점이 복잡하면 마지막 번호를 사안포섭/결론반복으로 사용
- 단순 법리 확인형(Case 9)은 사안포섭 없이 명제만

### P-10. 목차/문제/F 섹션 전부 제거

- **문제**: 없음

## 3. 변동 패턴 (Case마다 다름)

### V-01. 번호 개수 (0 ~ 13개)

- **0개**: Case 9 (6점, 단순 법리 확인)
- **최소 2개**: Case 20 (복잡도 낮음 — 증명책임 핵심만)
- **평균 6~8개**: 표준
- **최대 13개**: Case 23 (임대차 비용상환·부속물·보증금 3중 쟁점)

**기준**:
- 점수 10점 이하 & 단일 쟁점 → 0~4개
- 점수 15~17점 & 단일 쟁점 → 5~8개
- 점수 20점 OR 복수 쟁점 → 8~13개
- **핵심**: 쟁점 개수가 번호 개수를 결정. 점수가 아님.

---

### V-02. 한 번호의 길이 (1줄 ~ 6줄)

- **1줄**: Case 12 번호 1 "제 109조 착오로 인한 의사표시는 법률행위 내용의 중요부분에 착오가 있다면 취소 할 수 있다"
- **3줄**: Case 19 번호 6 (제135조 요건 6개 나열)
- **5~6줄**: Case 5 번호 6, Case 7 번호 7 (판례 본문 이식)

**결정 기준**:
- 조문 요건 간단 나열 → 1~2줄
- 판례 본문이 핵심이면 → 그 번호만 5~6줄
- 학설 요약 → 없음 (판례만이므로 불필요)

---

### V-03. 결론 형식 (단문 vs 복문)

- **단문** (Case 4, 5, 12, 13, 24, 25, 29 일부): "~할 수 있다", "~이다"
- **복문** (Case 27, 30): 판례 이유 자체가 결론
- **병렬 결론** (Case 29): "A 부분은 X, 그 외 부분은 Y"

## 4. 케이스별 특수 처리

### 케이스 분할 (Case 8-1, 8-2)

**패턴**: PDF 한 Case에 설문 1 / 설문 2가 있고 각 설문이 독립된 결론·근거를 가질 때 → `8-1`, `8-2`로 분할.

**적용 기준**:
- PDF에 "Ⅰ. 설문 1.에 관하여 / Ⅱ. 설문 2.에 관하여" 또는 "설문 ①의 경우 / 설문 ②의 경우" 구조
- 각 설문이 서로 다른 법리를 다룸

**분할 금지**:
- 같은 사안에서 결론만 2개인 경우 (Case 10: ① 직접 청구 불가 ② 채권자대위) — Case 10은 한 개
- 한 쟁점의 병렬 결론 (Case 29: 건물 부분 / 그 외 부분) — Case 29는 한 개

**변환 가이드**:
- PDF 설문 번호 ≠ Case 분할 조건. 설문이 독립적 법리인지 판단.
- 분할 시 각 설문 내에서 "결론, 1, 2, ..." 새로 시작.

## 5. 사용자 작성본의 특이점 (R-09 관점)

### "제 397조" 띄어쓰기

- **판단**: 의도적 (30 Case 전체 일관). 오타 아님.
- **근거**: 조문번호는 시각적으로 구분되어야 한다는 사용자 습관
- **적용**: Lv.4 한정 유지. Lv.1/2/3은 R-19 따라 "제397조" (띄어쓰기 X).

### 학설 완전 생략

- **판단**: 의도적. 판례 중심 답안 스타일.
- **적용**: 학설 대립 주제여도 판례만 기재.

### 사안 포섭 선택적

- **판단**: 의도적. 쟁점 복잡도에 따라 포섭 여부 결정.
- **적용**: 쟁점 단순 → 포섭 생략, 복잡 → 마지막 번호에 포섭.

### 번호 개수 가변

- **판단**: 의도적. 쟁점 개수 기반.
- **적용**: 점수 아닌 쟁점 수에 맞춰 번호 조절.

## 6. R-09 의심 사례 (변환 서브 필독)

### Case 15 — 결론 방향 오류 의심

- **사용자 결론**: "매매계약은 적법하게 해제 되었다"
- **PDF 정답지 해시태그 ①**: "해제되지 않았다"
- **판단**: 번호 8 (본문)은 판례 방향 맞음. 결론 한 줄 요약이 반대 방향.
- **변환 가이드**: **PDF 우선**. 결론 "해제되지 않았다, 매수인의 중도금 송금이 이행 착수이므로"로 재작성.

### Case 20 — 결론 문장 애매

- **사용자 결론**: "은행의 무권대리의 주장은 받아들여 질 수 있다"
- **PDF 정답지 해시태그 ①**: "인용될 수 있다" (A은행의 제135조 청구)
- **판단**: "은행의 무권대리의 주장"이 애매 — "은행이 원고로서 무권대리에 기한 손배청구를 주장"이 정확한 의미
- **변환 가이드**: 다른 유사 Case에서도 **PDF 해시태그 문장을 결론으로**. 사용자 표현은 참고.

### 일반 원칙

**사용자 작성본 vs PDF 해시태그 충돌 시**:
1. PDF 해시태그 우선 (정답)
2. 사용자 본문(번호 1~N)이 PDF 판례 방향과 일치하면 본문 유지, 결론만 수정
3. 의심 케이스는 가이드 문서에 기록 후 사용자에 확인 요청

## 부록: Case 1 풀 예시 (PDF → Lv.4)

### PDF 원본 (요약)
- 사실관계: 갑이 을에게 2015.1.1. 1000만원 대여, 변제기 2015.12.31, 이자 약정 없음. 2016.3.31. 현재.

- 결론 해시태그 ①: "모두 청구할 권리가 있다"

### Lv.4 변환 결과
```
Case 1.
결론, 원금과 지연손해금을 청구 할 권리가 있다.
1. 청구의 병합,
소비대차계약 기한 반환 청구와 지연손해금은 별개의 소송물로 객관적 병합에 해당한다.
```
